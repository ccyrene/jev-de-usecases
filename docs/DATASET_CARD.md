# Dataset card — de-laya-jev-th-en-2026

**Version:** e0X-v1 question sets, seed `20261019`, built 2026-10-19.
**Content:** 6 use cases × 300 scenarios × {EN, TH} = 3,600 language records per context level
(`common_fit`, `natural_long`; E05 also `equal_information`). Every record is synthetic.

## How it was made

Each scenario starts from an **injected, language-invariant fault** generated by
`src/debench/dataset/eXX.py` with `random.Random(seed + case offset)`. The fault seeds a real
database engine (with distractors), a fixed provider-independent query retrieves the evidence, and
`oracle_check` compares the DB result with an independent pure-Python reference of the same facts
(networkx for lineage, pandas for data quality, the generator's migration model for schema drift,
multi-snapshot execution for SQL). Gold labels come from documented deterministic policies over
those verified facts (each policy is in its module docstring) — never from a model.

EN and TH states are rendered from the same facts. Machine tokens (IDs, SQL, error strings,
numbers, timestamps, column names) are byte-identical; Arabic digits only; field keys identical.
`paired_generator.validate_pair` and `payload.assert_no_leakage` run on every record.

## Splits

Grouped by template/incident family (`group_id`); no group crosses splits
(`tests/test_pair_equivalence.py`). dev 60 / calibration 40 / test 200 per case, except E06
(dev 59 / calibration 40 / test 201) because whole groups cannot hit the targets exactly.
A predeclared 50-scenario P4 subset is drawn from each test split.

## Why the gold is trustworthy — and where it is policy

- Facts are measured by the engine and cross-checked by an independent implementation.
- Labels are deterministic policies over those facts. Where a label is a policy choice rather than
  hidden truth (E05 free text → `unknown`; E03 type change with all consumers passing →
  `type_or_cast_break`; E06 execution errors → `semantically_wrong`), the module docstring says so.
- Because rules baselines read the same verified facts, E02/E04 rules are near-oracles by
  construction; the benchmark measures whether a decision model can read the *rendered* evidence.

## Language and safety

- Thai text is natural technical Thai with realistic code-switching (E01 246/300, E03 300/300,
  E06 220/300 records tagged `code_switching`). It was machine-drafted and model-reviewed;
  **no native Thai speaker has reviewed it yet**.
- E05 safety (`tests/test_no_real_pii.py`): every Thai national-ID lookalike fails the mod-11
  checksum, emails use example.com/.org/.net only, phones are from documented fictional ranges,
  names come from a fictional list, and samples are partially masked.
- No real company records, logs, or people are present.

## Intended use and limits

Benchmarking bounded decisions (choice/score/noul) over DB-derived evidence. Not a training set
for production triage, not legal PII classification, and not a SQL-generation benchmark.
